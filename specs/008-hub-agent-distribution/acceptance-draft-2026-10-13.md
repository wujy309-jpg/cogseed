## 四·补、真 Hub 联调发现的问题

客户端已修（`e1dc455b`、`05a0986a`）：
1. 可选文本字段为空串（本机自建 Agent 的 `description_en` 常见）：Hub 直接拒绝。提交前移除，预览里列为"空字段"。
2. 没有 `skill_list` 的 Agent：协议里可选，Hub 引用解析却把缺省当"不是数组"拒绝。提交前补空数组。
3. 提交成功后的跳转落在技能页签。改为留在智能体页签。
4. 依赖技能状态为 `published`（真 Hub 的写法）时被判为"未批准"而拒装。改为 `published` 与 `approved` 均可安装。

**待 Hub 侧处理（已核对 Hub 代码）：**
- `GET /marketplace/contributions/mine` 的条目**没有 `content_type`**，带 `?content_type=` 参数返回 **400**。后果：客户端按"智能体"筛选时，已提交的 Agent 不显示；缺类型的条目被默认当作 Skill。该接口仍是 Skill 一轮的 C-04 实现。
- `skill_list` 缺省应视为空数组（与协议"可选"一致）。

**已处理（客户端侧，`fe7f8539` 及其后续提交）：**
- **Hub 停用的市场 Agent，本机已装的**：不可用并提示"已被 Hub 停用"（跟随 Skill 的先例），不动用户偏好，Hub 恢复后自动恢复。**属产品行为，已按"先做、再告知"处理，待向中扬说明。**
- **同步只改状态时卡片不刷新**：主进程在本机安装记录有变化（含只改状态）时推送 `marketplace:installs-changed`，Agent 页（启动即加载）订阅并重读列表。注意监听必须放在 `agents.js`：`marketplace.js` 是懒加载的。

## 五、结论与风险

- 已验证的主路径（市场 → 预览 → 安装 → 自动更新 → 卸载）在真实应用连真 Hub 下通过，并发现修复一处缺陷（#5）。
- **验收仍欠**：B/C（依赖场景，需 Hub 上有已发布且可用的技能）、H（Windows）。贡献的真实端到端已通。
- 真 Hub 联调发现并修复客户端**四**处问题（空串字段、缺省 skill_list、提交后页签、依赖状态 `published`），并补上两项缺口（Hub 停用的 Agent 本机不可用、状态变化自动刷新卡片）；Hub 侧待处理两处。
- 本底稿不代表契约联合冻结，也不代表发布验收。
