# Agent 分发与贡献：客户端与 Hub 两边的处理方式（v3）

- **收件人**：中扬（产品）　**发件人**：史雨萱（客户端）　**日期**：2026-10-13
- **怎么读**：下面每一条都是**两边已经定好、按此执行**的处理方式，不需要逐条拍板。只有我们定不了的，列在**最后一节**，共 4 条。
- 状态：客户端已按这些做完并通过自动化检查；Hub 接口联调还没开始，联调由 Hub 牵头。

---

## 一、安装 Agent 时，它依赖的技能怎么处理

**本机已有该技能，且可用**
- 客户端：直接用，不升级。别的 Agent 也可能在用它，不能因为装一个 Agent 去改动它。
- Hub：无动作。

**本机没有该技能**
- 客户端：从 Hub 补装，装当前最高已发布版本。
- Hub：目录只返回最高已发布版本。

**最高版本要求更高的客户端**
- 客户端：阻断，提示"需 CogSeed x.y 以上"，不去装旧版本。
- Hub：本期不支持回退到较旧的兼容版本。
- 影响：客户端较旧的用户，会装不上个别 Agent。

**技能被 Hub 停用**
- 客户端：安装前就阻断并说明原因。已装的 Agent 卡片显示"依赖已停用"，"使用"不可点。只影响这一个 Agent，不影响别的 Agent 和进行中的任务。
- Hub：要停用某个技能，必须先停用依赖它的 Agent，否则拒绝（`409 CONTENT_IN_USE`）。所以"本机装了、Hub 却停了"只会出现在这个先后窗口里。

**装的过程中任何一步失败**
- 客户端：整个 Agent 不记录；原有的 Agent、已装技能、进行中的任务都不受影响。

**装完之后依赖技能有新版本**
- 客户端：走技能自己的更新通道，Agent 不触发升级；进行中的任务继续用已固定的版本。

## 二、Agent 自己有新版本时

**怎么发现有新版本**
- Hub：以 Agent 目录为准，比较版本号和发布物摘要。
- 客户端：必须翻完整个目录才下结论；目录里找不到不算有更新；停用不算新版本；版本比本机低也不降级。

**更新时**
- 自动跟随，与技能一致；进行中的任务不受影响。
- 随包私有技能整体替换，不与旧版混用。**本地对随包技能做的修改会丢**，这是明确的代价。
- 新版本依赖的 Hub 技能：已有的复用，缺的补装，同第一节。
- 更新前后用户的启用/停用选择保持不变；用户停用的 Agent 也会更新，更新后仍保持停用，不替用户启用。

**更新失败**
- 保留旧版，继续可用；卡片和详情页提示"更新失败，仍可使用 x.y"。

**本期不做**：停在旧版、"转为我的版本"。

## 三、贡献时正文里的本机路径和密钥

- 客户端：只拦明显的密钥格式（SSH 私钥、pem 等），拦住就不允许提交；移除不该分发的字段（版本、时间戳、连接器配置、模型偏好等）。
- 预览页：把正文和随包文件里明显的本机路径（如 `/Users/xxx/发票/`）、疑似凭据**高亮**出来，用户勾选"已知晓"才能提交。**只高亮，不自动改写**，不穷举，不做长期规则库。
- Hub：字段剥离分两层——客户端先剥，Hub 服务端再按白名单把关，出现多余字段直接拒绝（`UNEXPECTED_FIELD`）。Hub 不知道客户端高亮了什么。

## 四、随包私有技能的用户可见规则

- 随 Agent 一起安装，只有这个 Agent 能用。
- 不出现在用户自己的"技能"列表，也不在 Hub 技能市场里单独出现。
- 不覆盖用户本机的同名技能。
- 卸载 Agent 时一并移除。
- 点"贡献"时提示"这些技能也会同时贡献"，用户同意才提交，只有一次确认。

## 五、Agent 引用客户端内置能力（`builtin:<名字>`）

- 客户端：本期开放 3 个——资料问答（grounded-material-qa）、知识库思维导图（kb-mindmap）、coding。清单外的一律不允许贡献。
- 使用时：本机具备就直接用，不下载；不具备（版本不够等）就阻断这个 Agent，不去下载。
- Hub：维护这份清单，清单外的内置引用一律拒绝；清单为空时也是拒绝，不会放行。
- 客户端发请求时只带开放线标识，所以联调要用开放线的技能。
