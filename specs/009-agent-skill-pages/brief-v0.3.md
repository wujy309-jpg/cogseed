## 变更说明（v0.2 → v0.3）

走查可点击原型后调整如下。**R1 是本版设计稿的默认做法，不同类别的智能体放在哪里仍待产品确定。**

1. **页面分工（R1，待定）：** 本版设计稿分三处：**首页**只放能去安装的平台分发内容；**"我的"**只放我自己的（自定义、从平台安装的、外接），是一个网格，每张卡有来源标记，顶部可按来源筛选；**"管理"**单独放统一配置好的内置和平台预置内容，只有启用 / 停用开关。这与 2026-10-15 会上"内置先继续放着"的口头说法不同，需中扬确认。
2. **"使用"落到详情弹窗（R3）：** 点"使用"打开详情弹窗，不新设计任务页，弹窗之后沿用现有新任务流程。
3. **安装保持简单（R9）：** 只保留"安装中…、已安装、失败可重试"三种状态，不展示进度和步骤。

## 1. 要交付什么

**用户打开"智能体"和"技能"页面，看到的是平台分发的内容，能直接浏览、安装或使用；"我的智能体 / 我的技能"收纳"我自己的"：自己创建的、从平台安装的、外接或本机已有的。点进任一智能体或技能，看到的是"它能做什么、怎么用"，点"使用"直接进入新任务。**

S3 已完成智能体和技能的分发。S4 的目标是把这些分发内容真正放到页面首页上，结构参照 WorkBuddy 与豆包 Work。

## 2. 起点与参考

- 现状：两个页面以客户端内置内容为主，入口里有"更多"按钮，点进去才到市场；自定义、全局文件夹等用户自己的内容和平台内容混在同一页展示。
- 现状：页面数据来自本地，没有加载过程；点进智能体或技能后展示的是内部结构，对用户没有价值。
- 参考一：WorkBuddy。首页是平台分发的"专家 / 技能"；用户自己的内容通过"我的专家""我安装的"入口查看；点开是弹窗，有用途、标签、"帮你做"的示例行。
- 参考二：豆包 Work。卡片带"N 万人在用"和"安装"按钮；技能详情是弹窗。
- 参考三：樊中扬已改的会议 MCP 页面。点开后展示能做什么、可以怎么用，附示例，点击即可发送使用。
- 本轮细化前，先核对 Hub 现有接口和页面，明确可复用项与缺口。

## 3. 主流程

### A. 发现并使用平台内容

用户进入智能体 / 技能页面 → 首页看到平台分发的内容（已安装的带标记） → 点卡片或"使用"，打开详情弹窗，看到能做什么和示例 → 未安装：点"安装"，按钮变"安装中…"，完成后变"使用" → 在弹窗里点"使用智能体"或点示例，进入现有的新任务流程。

### B. 使用和管理"我的"

用户点首页的"我的智能体 · N" → 看到自己的东西：一个网格，卡片带来源标记，顶部可按来源筛选（全部 / 自定义 / 平台 / 外接 Agent，技能为"本机已有"） → 点"使用"打开详情弹窗；自建内容点"管理"，已安装的平台内容可"卸载"，内置内容不可卸载。

### C. 创建

首页工具栏或"我的"页点"创建智能体 / 创建技能" → 弹窗填写（智能体另有"外接"） → 确认后进入"我的"，新卡片出现在"我创建的"（外接的在"外接 Agent"）。

## 4. 已定的产品规则

以下规则作为设计与实施的默认值，评审时由中扬确认。**带"变更"的是 v0.3 相对 v0.2 的调整。**

| 编号 | 规则 | 理由 |
|---|---|---|
| R1（**待定**） | 本版设计稿的做法：**首页 = 能去安装的平台分发内容**，单一网格；**"我的" = 我自己的**，是**一个网格**，不分组；每张卡带来源标记（自定义 / 平台 / 外接 Agent，技能为"本机已有"），顶部有来源筛选（全部 / 自定义 / 平台 / 外接 Agent）；**"管理" = 统一配置好的内容**（客户端内置 + 平台预置、默认开启的），只有启用 / 停用开关，不能安装、卸载、编辑。**各类智能体放在哪里，由产品再定**，本条仅为设计默认值。 | 统一配置的内容用户不装也不删，只需要开关，不该占商店或"我的"的位置；"我的"和首页因此更干净；Hub 不可用时内置与预置仍可管理 |
| R2 | **详情统一为一种弹窗**，内置、预置、平台、自建都一样；版式照客户端已有的"连接器使用弹窗"：标题栏是图标 + 名称 + 说明行（类别、版本、在用人数）+ 关闭；正文依次是简介、标签、"智能体帮你做"示例（整行按钮，点一下发送）、会用到的技能（标注是否就绪）；操作（使用 / 安装、卸载 / 管理 / 停用）在底部。技能详情另有"能做什么"。主按钮"使用"；自建另有"管理"（进入现有编辑工作台）；已安装的平台内容另有"卸载"；内置和预置另有"启用 / 停用"，没有卸载。 | 同一概念不做两套详情 |
| R3（变更） | **点卡片或"我的"里的"使用"，打开该项的详情弹窗**（即第 2 组设计稿的"详情弹窗"）。弹窗里点"使用智能体 / 使用技能"或点示例，进入客户端现有的新任务流程（本期不新设计任务页）；点示例即发送。未安装时示例照常显示（不置灰），点击提示"请先安装"；已停用时才置灰。 | 与 WorkBuddy 一致，弹窗承担"了解 + 开始使用"；任务页沿用现有 |
| R4（变更） | **Hub 不可用时**，首页顶部给"暂时无法获取平台内容"和重试，并指引去"我的"使用已安装内容；"我的"不受影响。 | "我的"本地可用，首页只是商店 |
| R5 | **创建入口**首页工具栏和"我的"页都有；"我的"里"我创建的"为空时给出引导。 | 新用户从首页就能找到创建 |
| R6 | 分类沿用各自 spec 里的定义，两侧不强求一致；首页和"我的"都提供搜索（支持中文输入法，输入过程不丢焦点）。 | 分类由 `agent.json` / SKILL.md 决定 |
| R7 | 在用人数、标签是**可选字段**：Hub 提供就显示，没有就不显示。 | 避免因字段缺失卡住上线 |
| R8 | 新版本、已下架、卸载有依赖的处理规则见第 7 节；本期先定规则，设计稿下一版补画。 | 控制范围 |
| R9（变更） | **安装保持简单：** 点"安装"后按钮变"安装中…"（不可重复点击），完成后变"使用"并给出"已安装"提示；失败时卡片保留，显示"安装失败，可重试"，详情给出原因和"重试"，且不破坏已有内容。不展示百分比、步骤或文件数。 | 用户只需要知道"在装、装好了、没装成" |
| R10（新增） | **管理页**：入口在首页工具栏最右（"管理"），智能体页、技能页各一个；页面分"内置""平台预置（默认开启）"两组，每行只有图标、名称、简介和一个开关（即现有的"停用 / 启用"）；页头显示"已启用 N / 共 M"；点一行打开同一种详情弹窗（只读，另有"启用 / 停用"，没有卸载、管理）；停用后任务里不再调用、@ 也找不到。**需 Hub 能标出"预置、默认开启"的内容（D-01）。** | 借鉴豆包工作的"管理"页：统一配置的内容只做开关 |

## 5. 需求范围

编号用于本 Brief 的需求追溯。

| 编号 | 需求项 | 必须细化的内容 | 对应结果 |
|---|---|---|---|
| S4-01 | 智能体页面架构 | 首页只放平台分发内容；去掉"更多"并把原"更多"内容并入首页；"我的智能体"收纳我创建的、从平台安装的、外接 Agent（R1）；新增"管理"页放内置与平台预置（R10） | 首页是平台"商店"；"我的"是"我能用的全部" |
| S4-02 | 技能页面架构 | 同 S4-01：首页不展示自定义与全局文件夹；"我的技能"收纳我创建的、从平台安装的、本机已有（全局文件夹）（R1）；"管理"页放内置与平台预置（R10） | 同上 |
| S4-03 | 详情与使用路径 | 统一弹窗（R2）；能做什么、示例、一键发送；点"使用"打开详情弹窗（R3）；去掉 ontology、`schema.json` 等内部结构 | 用户不需要理解实现，就能知道价值并开始使用 |
| S4-04 | Hub 数据、加载与安装 | 列表只返回摘要，详情在安装时获取；首页加载中、空态、失败态（R4）；安装中、完成、失败（R9）；可选字段降级（R7） | 页面请求 Hub 后仍然顺畅；失败有明确提示且不影响已有内容 |
| S4-05 | 创建 | 创建智能体（创建 / 外接）和创建技能的弹窗、校验（名称必填、字符限制、保留名、重名）、创建后落点（R5） | 创建流程可走通 |
| S4-06 | 高保真设计稿与可点击原型 | 覆盖智能体和技能；首页、"我的"、详情、加载 / 失败 / 安装 / 空态、创建 | 评审通过后再进入 Spike 与实施 |

### 内容来源区分

- 客户端内置：打包在客户端里，不能安装、卸载；只在"管理"页出现，只能启用 / 停用。
- 平台预置：Hub 分发、随客户端预置且默认开启的内容；同样只在"管理"页出现，只能启用 / 停用。
- 平台分发：Hub 创建并分发；首页展示；安装后同时出现在"我的"的"从平台安装"。
- 用户自己的：自建的、本机已有的（含全局文件夹）、外接 Agent、外部包；只在"我的"出现。

## 6. 本轮边界

### 纳入

- 两个页面的信息架构调整（S4-01、S4-02）。
- 详情与使用入口（S4-03）。
- Hub 数据读取、加载、安装体验（S4-04）。
- 创建流程（S4-05）。
- 高保真设计稿与可点击原型（S4-06）。

### 不纳入

- MCP、连接器等其他模块的页面改版。
- Hub 端主动发起的新需求；Hub 只配合客户端设计所需的调整。
- 推荐功能（"是否安装"的推荐提示）。
- 新的分发、贡献、审核机制；沿用 S3。
- 首页的"精选场景""精选技能"横幅、排序（综合、最热、最新）：参考产品有，本期不做。
- "管理"进入的编辑工作台、"使用"之后的新任务页：沿用现有，不在本期改版。

## 7. 细化时必须覆盖的异常

- Hub 不可用、网络中断或请求超时：按 R4；"我的"照常可用。
- 列表为空或没有平台分发内容；搜索无结果；"我创建的"为空：各有空态。
- 安装失败、断网中断：按 R9；卡片不消失，可重试。
- 技能文件较多、安装较慢：按钮保持"安装中…"，不重复点击。
- 用户自己的内容与平台内容重名：卡片标注来源。
- 本机全局文件夹扫描到的技能：归入"我的技能"的"本机已有"，不回到首页。
- **有新版本**：已安装的平台内容在首页卡片和"我的"里提示"有更新"，点击更新；更新失败保留旧版（沿用 S3-05）。
- **已下架**：Hub 已下架但本机已装的，保持可用，不再出现在首页，在"我的"里标注"已下架"。
- **卸载有依赖**：卸载技能时，若有已安装的智能体在使用它，先提示"智能体 X 在用此技能"，允许继续卸载，该智能体标缺失依赖（沿用 S3 的依赖异常规则）。

## 9. 完成标准

| 场景 | 必须观察到的结果 |
|---|---|
| 智能体首页 | 只有平台分发内容；没有"更多"；没有内置、预置和自建内容；工具栏有搜索、创建、"我的智能体 · N"和"管理" |
| 技能首页 | 同上；全局文件夹扫描到的技能不出现在首页 |
| 我的内容入口 | "我的智能体"和"我的技能"对称：我创建的、从平台安装的、外接或本机已有的都能找到，没有内置和预置；有搜索；为空时有引导 |
| 管理 | 首页工具栏有"管理"入口；页面分"内置"和"平台预置（默认开启）"，每行只有一个开关；页头显示"已启用 N / 共 M"；停用后任务里不再调用；没有安装、卸载、使用按钮 |
| 详情与使用 | 点进任一内容，是同一种弹窗；看到能做什么和示例；自建有"管理"，已安装的平台内容有"卸载"，内置和预置只有"启用 / 停用"；界面不出现内部结构 |
| 使用 | 点卡片或"我的"里的"使用"，打开详情弹窗；弹窗里点主按钮或示例后进入现有新任务流程，示例会直接发送 |
| 安装 | 点安装后按钮变"安装中…"，完成后变"使用"并提示已安装；断网或失败时卡片保留、显示失败和重试，已有内容不受影响 |
| 创建 | 创建、外接两种方式都能走通；校验提示正确；创建后进入"我的"并看到新卡片 |
| 断网 | 首页提示获取失败并可重试；"我的"照常可用 |
| 搜索 | 首页和"我的"可输入过滤；无结果有空态；中文输入不被打断 |
| 更新、下架、卸载依赖 | 按第 7 节规则表现（本期设计稿可不画，实施前补齐） |
| 双平台 | 在 macOS 与 Windows 上验证页面展示和使用路径 |

以固定 Hub / 客户端版本、测试环境和实际内容的结果记录作为验收依据。仅有设计稿或接口通过，不能代表 S4 完成。
