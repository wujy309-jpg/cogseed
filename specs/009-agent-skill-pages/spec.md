## Clarifications

### Session 2026-10-19

- Q: 卡片上点「安装」后是否自动进入任务？ → A: 不跳转，只安装并把按钮变「使用」；在详情里点示例才安装后直接发送（FR-011）。
- Q: 智能体安装时「将同时安装 xx 技能」确认框是否保留？ → A: 去掉，依赖直接补齐；安全扫描与质量检查确认照旧（FR-012）。
- Q: 「停用技能时提示受影响的智能体」是否纳入本次？ → A: 纳入（FR-027，User Story 5）。
- Q: 依赖的技能被用户停用后，智能体还能不能用？ → A: 不能，与 S3 平台停用依赖时的做法一致：「使用」与示例不可点，详情提供一键启用该技能（FR-027）。
- Q: 这种智能体，主智能体自动派活时怎么办？ → A: 照常派，只是不带被停用的技能（2026-10-20 定；运行时本来就把用户停用的技能从每个智能体的技能里去掉）。
- Q: 新的详情弹窗里要不要保留「有新版本时更新」的入口？ → A: 保留：卡片标「有更新」，详情底部加「更新」，复用 S3 已有的更新流程（失败保留旧版、运行中任务不换版本）（FR-013a）。
- Q: 用户没登录时，智能体页和技能页显示什么？ → A: 主智能体、外接、我的、已安装照常；平台组只显示已安装的并提示「登录后查看更多平台内容」；点安装、贡献时先提示登录（FR-024）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在首页发现并使用平台内容 (Priority: P1)

用户打开「智能体」或「技能」页，看到所有能用的东西：智能体页分「主智能体 / 外接智能体 / 平台」三组，技能页只有「平台」一组。平台组里的内容全部来自平台分发，不标来源，已安装的排在前面、没安装的排在后面。已安装的卡片按钮是「使用」，没安装的是「安装」。点卡片打开统一的详情弹窗，看到它能做什么和示例；点「使用」或点示例进入现有新任务流程。

**Why this priority**: 这是改版的核心价值——用户不用理解来源和内部结构，打开就能找到并开始用。

**Independent Test**: 只实现首页分组、卡片按钮状态与详情弹窗，即可在真实客户端验证「找到 → 了解 → 开始使用」。

**Acceptance Scenarios**:

1. **Given** 用户已登录、平台可访问，**When** 打开智能体页，**Then** 依次看到「主智能体」「外接智能体」「平台」三组；平台组内已安装的在前、未安装的在后；卡片上没有「客户端内置 / 平台分发 / 平台预置」等来源字样，也没有「N 人在用」。
2. **Given** 打开技能页，**When** 页面加载完成，**Then** 只有「平台」一组；没有自建技能、外部包、全局文件夹技能。
3. **Given** 一个已安装的平台智能体，**When** 点卡片，**Then** 打开详情弹窗：标题栏是图标 + 名称 + 「分类 · 平台 · 版本」，正文有简介、标签、「智能体帮你做」示例、会用到的技能（标明是否就绪），底部主按钮「使用智能体」，另有「停用」「卸载」。
4. **Given** 详情弹窗已打开，**When** 点一条示例，**Then** 关闭弹窗，进入新任务并直接发送该示例。
5. **Given** 一个已停用的内容，**When** 查看卡片或详情，**Then** 卡片变暗并标「已停用」，「使用」和示例不可点；详情里有「启用」，启用后恢复可用。

### User Story 2 - 安装平台内容 (Priority: P1)

没安装的平台内容，卡片和详情只有一个「安装」按钮（详情里为「安装智能体 / 安装技能」）。点了显示「安装中…」，装好后提示已安装、按钮变「使用」，页面不跳走。在详情里直接点示例，则先安装、装好后直接进入新任务并发送示例，一步完成。安装失败时卡片保留并可重试。

**Why this priority**: 内容必须先下载到本机才能运行，安装是使用平台内容的前提；交互要让用户一眼看出哪些需要先装。

**Independent Test**: 在首页对一个未安装内容分别走「点安装」「详情里点示例」「断网下安装后重试」三条路径即可验证。

**Acceptance Scenarios**:

1. **Given** 一个未安装的平台智能体，**When** 点卡片上的「安装」，**Then** 按钮变「安装中…」且不可重复点；完成后提示「已安装」，按钮变「使用」，该卡片移到已安装区，工具栏「已安装的智能体 · N」加 1，不自动进入任务。
2. **Given** 未安装内容的详情弹窗，**When** 点一条示例，**Then** 弹窗内显示「安装中…」；完成后关闭弹窗、进入新任务并发送该示例。
3. **Given** 安装过程中网络中断，**When** 安装失败，**Then** 卡片保留并显示「安装失败，可重试」；详情给出原因和「重试」；已有内容不受影响；不进入任务。
4. **Given** 安装时安全扫描或质量检查需要用户确认，**When** 触发，**Then** 沿用现有的风险卡 / 质量报告确认流程。
5. **Given** 安装一个依赖其他技能的智能体，**When** 安装，**Then** 依赖技能被一并装好后智能体才显示可用（沿用 S3 的依赖自动补齐）；不再弹「将同时安装」确认框（FR-012）。

### User Story 3 - 在「已安装」里集中停用和卸载 (Priority: P1)

首页工具栏最右是「已安装的智能体 · N」/「已安装的技能 · N」，进入后列出所有从平台安装的内容（包括老用户升级后迁移过来的原随包内容），每行有「卸载」和启用 / 停用开关，页头显示「已启用 N / 共 M」。

**Why this priority**: 平台内容统一走平台分发后，所有装到本机的平台内容都要有一个集中停用、卸载的地方；它们都可能被主智能体自动调用。

**Independent Test**: 进入「已安装」页对一行分别停用、启用、卸载，回首页核对卡片状态。

**Acceptance Scenarios**:

1. **Given** 老用户升级后本机已有原随包内容，**When** 打开「已安装的智能体」，**Then** 这些内容与用户自己装的一起列出，都能停用和卸载；没有「自带」分组，也没有不能卸载的行。
2. **Given** 一行处于启用状态，**When** 关掉开关，**Then** 页头计数减 1；回首页该卡片标「已停用」；主智能体在新任务中不再调用它，@ 也找不到。
3. **Given** 一行，**When** 点「卸载」，**Then** 从「已安装」页消失；回首页该卡片回到「安装」状态。
4. **Given** 用户没有安装任何平台内容，**When** 打开「已安装」页，**Then** 显示空态并说明点「安装」后会出现在这里。
5. **Given** 主智能体、外接智能体、用户自建内容、本机已有技能，**When** 打开「已安装」页，**Then** 它们都不在这里。

### User Story 4 - 在「我的」里管理自己的东西并贡献 (Priority: P2)

「我的智能体」只放用户自己创建的；「我的技能」是一个网格，放用户自建的和本机已有的技能（外部包、全局文件夹扫描到的），卡片标「自定义 / 本机已有」，顶部可按「全部 / 自定义 / 本机已有」筛选。自建卡片可「贡献」到平台；「我的」页工具栏有「+ 创建」和「我的贡献」（首页工具栏不放）。本机已有的技能在这里停用；外部包可在详情里移除；顶部说明条有全局文件夹总开关。

**Why this priority**: 「我的」是用户自己内容的唯一归处，一样东西只放一处，避免与首页、「已安装」混淆。

**Independent Test**: 进入「我的智能体」「我的技能」，分别验证创建、贡献入口、来源筛选、本机已有技能的停用与外部包移除、总开关。

**Acceptance Scenarios**:

1. **Given** 用户有自建智能体，**When** 打开「我的智能体」，**Then** 只看到自建的；没有平台内容和外接智能体；每张卡片有「贡献」；工具栏有「+ 创建」「我的贡献」。
2. **Given** 打开「我的技能」，**When** 页面加载，**Then** 一个网格：自定义的在前、本机已有的在后；卡片标来源；外部包卡片显示包来源；本机已有的没有「贡献」。
3. **Given** 「我的技能」，**When** 选「本机已有」筛选，**Then** 只剩外部包和全局文件夹技能。
4. **Given** 顶部总开关「读取全局技能文件夹」开着，**When** 关掉，**Then** 全局文件夹技能从列表消失并说明「已关闭读取，文件本身不受影响」，主智能体也不再调用它们。
5. **Given** 外部包技能的详情，**When** 点「移除」，**Then** 先确认（说明会一并移除它带的 N 个技能），确认后从「我的技能」消失。
6. **Given** 点「我的贡献」，**When** 进入，**Then** 打开客户端现有的「我的贡献」页；返回回到「我的」。
7. **Given** 在「我的」点「+ 创建」完成创建，**When** 创建成功，**Then** 新卡片出现在「我的」；若是外接智能体，出现在首页「外接智能体」组。

### User Story 5 - 停用技能时知道会影响谁 (Priority: P3)

用户停用一个技能时，若有智能体会用到它，先提示「智能体 X、Y 会用到它，停用后它们将暂时不能使用」，确认后再停；被影响的智能体暂时不能使用，在详情「会用到的技能」里把该技能标为「已停用」，卡片上也有提示，详情可一键启用该技能恢复。

**Why this priority**: 停用对所有智能体生效，不提示时用户会觉得智能体「莫名变笨」。S3 只覆盖了平台停用的情况，用户自己停用的情况要补。

**Independent Test**: 停用一个被智能体引用的技能，验证停用前提示与停用后智能体的标记。

**Acceptance Scenarios**:

1. **Given** 技能 A 被智能体 X 引用，**When** 用户停用 A，**Then** 先弹出提示列出 X；取消则不停用；确认后停用。
2. **Given** 技能 A 已被用户停用，**When** 查看智能体 X 的卡片和详情，**Then** 卡片有依赖已停用的提示且「使用」不可点；详情「会用到的技能」里 A 标为「已停用」，「使用」与示例不可点，底部有「启用 A」，点后恢复可用。
3. **Given** 技能 B 没有被任何智能体引用，**When** 停用，**Then** 不弹依赖提示。

---

### Edge Cases

- **断网 / 平台不可用**：首页顶部提示「暂时无法获取平台内容」+ 重试；平台组只显示已安装的，照常可用；「我的」不受影响；不做离线兜底。
- **未登录**：本机内容照常可用；平台组只显示已安装的并提示登录后查看更多；安装、贡献先要求登录（FR-024）。
- **首页加载中**：主智能体、外接智能体与已安装内容先显示，未安装的平台内容位置显示骨架屏。
- **平台暂无更多内容**：平台组只显示已安装的，并说明暂时没有更多可安装的。
- **搜索 / 分类无结果**：显示空态与「清除筛选」；搜索支持中文输入法，输入过程不丢焦点。
- **内容缺少示例**：平台内容暂未提供示例时，详情显示一条通用示例（「请用 X 帮我处理这项工作」），不留空。
- **重名**：创建时与现有内容重名提示修改。
- **已停用内容**：卡片仍可点开详情并在详情里启用。
- **外部包被移除**：其带的技能一并从「我的技能」消失。
- **卸载被智能体依赖的技能**：先提示「智能体 X 在用此技能」，允许继续，该智能体标缺失依赖（沿用 S3 规则）。
- **新版本**：卡片标「有更新」，详情里「更新」；更新失败保留旧版（FR-013a，原型未画）。
- **已下架**：平台已下架但本机已装的保持可用，在「已安装」里标「已下架」（沿用 S3，原型未画）。

## Requirements *(mandatory)*

### Functional Requirements

**首页与分组**

- **FR-001**: 智能体页首页 MUST 分「主智能体」「外接智能体」「平台」三组，顺序固定；技能页首页 MUST 只有「平台」一组。
- **FR-002**: 平台组 MUST 列出全部平台分发内容（含老用户迁移来的原随包内容），MUST NOT 显示来源标记；排序 MUST 为已安装在前、未安装在后。
- **FR-003**: 首页 MUST NOT 显示用户自建内容、外部包技能、全局文件夹技能和系统内置技能。
- **FR-004**: 首页工具栏 MUST 包含分类、搜索（带搜索图标）、「我的智能体 / 我的技能 · N」与「已安装的智能体 / 已安装的技能 · N」，MUST NOT 包含「+ 创建」「我的贡献」「更多」。
- **FR-005**: 卡片和详情 MUST NOT 显示「N 人在用」类数字。

**详情与使用**

- **FR-006**: 所有类型内容点卡片 MUST 打开同一种详情弹窗（照现有连接器使用弹窗的版式），显示名称、说明行（分类 · 来源类别 · 版本）、简介、标签、示例、会用到的技能（智能体）或能做什么（技能），不展示内部结构（如工作流程原文、schema）。
- **FR-007**: 详情底部操作 MUST 按类型区分：主智能体只有「使用」；外接智能体另有「管理 / 停用」；自建另有「贡献 / 管理 / 停用」；已安装的平台内容另有「停用」，有新版本时另有「更新」（卸载只在「已安装」页，2026-10-20 定）；外部包技能另有「停用 / 移除」；全局文件夹技能另有「停用」。
- **FR-008**: 点「使用」或示例 MUST 进入客户端现有的新任务流程并选中该智能体 / 技能；点示例 MUST 直接发送该示例。
- **FR-009**: 已停用的内容 MUST 置灰「使用」与示例，并允许在详情中启用。

**安装**

- **FR-010**: 未安装的平台内容 MUST 显示「安装」（卡片与详情一致，2026-10-20 定）；安装中 MUST 显示「安装中…」且不可重复触发；安装完成后按钮 MUST 变「使用」并给出已安装提示。
- **FR-011**: 卡片上点「安装」后 MUST 停留在当前页面、不自动进入任务；在未安装内容的详情里点示例 MUST 先安装、成功后直接进入新任务并发送该示例。（2026-10-19 确认：Q1 = A）
- **FR-012**: 安装依赖其他技能的智能体时 MUST 直接一并补齐依赖，MUST NOT 再弹「将同时安装 xx 技能」确认框（依赖在详情「会用到的技能」里事先可见）；安全扫描、质量检查的确认 MUST 沿用现有流程；依赖被阻断（平台停用、客户端版本不够）时 MUST 提示原因并不安装。（2026-10-19 确认：Q2 = A）
- **FR-013**: 安装失败 MUST 保留卡片，显示「安装失败，可重试」，详情给出原因与「重试」，且不破坏已有内容、不进入任务。
- **FR-013a**: 已安装的平台内容有新版本时，卡片 MUST 标「有更新」，详情底部 MUST 提供「更新」；更新 MUST 复用现有更新流程：更新失败保留旧版并提示，运行中的任务不替换版本，新任务才用新版。

**已安装**

- **FR-014**: 「已安装的智能体 / 技能」页 MUST 列出所有从平台安装到本机的内容，包括老用户迁移来的原随包内容与默认安装的内容，不再区分「自带」；以一行三个的卡片展示（窄窗口自动减列），每张卡片 MUST 有启用 / 停用开关，「卸载」放在卡片的「⋯」菜单里，且「卸载」只在本页提供（详情弹窗不提供）；页头为一行（返回 · 状态筛选「全部 / 有更新 / 已停用」· 搜索），下方一行摘要写明总数、已停用数、有更新数；有更新、被阻断、已停用的排在前面（2026-10-20 改版）；为空时 MUST 显示说明性空态。
- **FR-015**: 主智能体、外接智能体、用户自建内容、本机已有技能 MUST NOT 出现在「已安装」页。
- **FR-016**: 停用 MUST 使该内容在新任务中不被主智能体调用、不可被 @，并在首页卡片上标「已停用」；卸载 MUST 使其回到「安装」状态。

**我的**

- **FR-017**: 「我的智能体」MUST 只列用户自建智能体；「我的技能」MUST 以一个网格列出自建技能与本机已有技能（外部包、全局文件夹），自建在前，卡片标「自定义 / 本机已有」，并提供「全部 / 自定义 / 本机已有」来源筛选。
- **FR-018**: 自建卡片 MUST 提供「贡献」；本机已有技能 MUST NOT 提供「贡献」。
- **FR-019**: 「我的」页工具栏 MUST 提供「+ 创建」与「我的贡献」；「我的贡献」MUST 打开客户端现有页面，返回时回到「我的」。
- **FR-020**: 「我的技能」顶部 MUST 提供全局技能文件夹总开关，关闭后全局文件夹技能 MUST 从列表中隐藏且不被调用，文件本身 MUST NOT 被修改。
- **FR-021**: 外部包技能 MUST 能在详情中「移除」，移除前 MUST 确认并说明会一并移除该包带的技能。
- **FR-022**: 创建流程 MUST 沿用现有「创建 / 外接」两种方式与校验（名称必填、字符限制、保留名、重名）；创建的进入「我的」，外接的进入首页「外接智能体」组。

**异常与状态**

- **FR-023**: 平台不可用时首页 MUST 提示并提供重试，平台组 MUST 只显示已安装的，「我的」与「已安装」不受影响；MUST NOT 随包提供离线兜底清单。
- **FR-024**: 未登录时，主智能体、外接智能体、「我的」「已安装」MUST 照常显示和使用；平台组 MUST 只显示已安装的，并提示「登录后查看更多平台内容」；点「安装」「贡献」MUST 先提示登录，MUST NOT 发起安装或提交。
- **FR-025**: 首页加载、平台暂无更多、搜索无结果、「我的」为空、「已安装」为空 MUST 各有对应状态。
- **FR-026**: 平台内容缺少示例时，详情 MUST 显示一条通用示例，不留空。

**停用依赖**

- **FR-027**: 用户停用一个被智能体引用的技能时，MUST 先提示受影响的智能体并允许取消；停用后受影响的智能体 MUST 暂时不可使用（「使用」与示例不可点，与平台停用依赖的现有行为一致），卡片与详情 MUST 标出依赖已停用，详情 MUST 提供一键启用该技能。主智能体自动派活时 MUST NOT 因此跳过该智能体，只是不带被停用的技能（2026-10-20 定）。智能体的技能清单里写的是技能 id 或技能名都 MUST 识别（与运行时一致）。（2026-10-19 确认：Q3 = A，纳入本次实施）

**通用**

- **FR-028**: 所有新增文案 MUST 提供中、英、日、葡四种语言。
- **FR-029**: 搜索 MUST 支持中文输入法，合成输入过程中不触发过滤、不丢焦点。

### Key Entities *(include if feature involves data)*

- **平台内容项**：平台分发的智能体或技能；属性：名称、分类、版本、简介、标签、示例、能做什么、依赖技能（智能体）、可用状态（正常 / 已下架 / 平台停用）。
- **安装记录**：某内容已装到本机；属性：内容、版本、安装时间、来源标记（用户安装 / 默认安装 / 原随包迁移）；本次界面统一视为「已安装」。
- **停用状态**：每个用户对某智能体或技能的启用 / 停用选择，对所有任务和智能体生效。
- **本机已有技能**：外部包（以包为单位，含若干技能）或全局技能文件夹中的技能；只读，不经平台。
- **自建内容**：用户在客户端创建的智能体或技能，可贡献到平台。
- **外接智能体**：接入本机已有工具（如 Codex、Claude Code）的智能体。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在原型走查与验收中，评审人从打开智能体页到开始使用一个已安装的平台智能体不超过 2 次点击；从未安装到使用不超过 3 次点击。
- **SC-002**: 首页、详情、「已安装」「我的」各页面中出现「客户端内置 / 平台预置 / 平台分发」来源字样和「N 人在用」的次数为 0。
- **SC-003**: 每个内容只在一个管理位置出现：平台内容在「已安装」，自建与本机已有在「我的」；验收抽查 100% 符合。
- **SC-004**: 断网时已安装的内容 100% 仍可使用，首页给出提示与重试；恢复网络后点重试可看到完整平台列表。
- **SC-005**: 安装失败后卡片 100% 保留并可重试，重试成功率与正常安装一致，已有内容无一受损。
- **SC-006**: 停用后的内容在新任务中被主智能体调用的次数为 0。
- **SC-007**: 在 macOS 与 Windows 两个平台上，以上主流程（发现、安装、使用、停用、卸载、我的、贡献入口、创建）全部走通并有记录。
