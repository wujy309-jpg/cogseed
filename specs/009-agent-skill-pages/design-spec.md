# S4 功能规格｜智能体 / 技能页面改版（客户端侧）

状态：Draft v0.4（规则编号与 brief-v0.4 不同，**以 brief-v0.4 为准**；本文侧重组件对照与代码落点）｜ 来源：2026-10-15 迭代会议；2026-10-18 会议 #2（结论见 [handoff-meeting2.md](handoff-meeting2.md)）；原型走查与代码调研（见 [brief-v0.4.md](brief-v0.4.md)）｜ 对应原型：[prototype/](prototype/)

## 1. 目标

用户打开「智能体」和「技能」页，就能看到所有可以用的东西，不需要知道它是客户端自带的还是平台分发的；没装过的平台内容按钮是「安装」，装好后变「使用」；在详情里直接点示例，会先安装再发送，一步完成。点进任一项，看到「它能做什么、怎么用」，而不是内部实现。用户自己创建的收进「我的智能体 / 我的技能」，从平台安装的在「已安装的智能体 / 已安装的技能」里集中停用或卸载；本机已有的技能（外部包、全局文件夹）在「我的技能」里管。

## 2. 现状（客户端真实实现，2026-10-19 核对）

| 位置 | 现状 |
|---|---|
| 智能体页（`src/renderer/modules/agents.js:966`） | 「AI 团队」按来源分四组：**主智能体 / 外接 / 自定义 / 平台**（平台 = 从市场装的和内置的；`normalizeCatalogSource` 已把 `builtin` / `platform` 都归为 `marketplace`），工具栏有「创建」「我的贡献」「更多」；点卡片进管理详情页 |
| 市场页（`marketplace.js`） | 「更多」进入，卡片 + 分类 + 搜索；点安装先弹「将同时安装」确认，再显示依赖进度 |
| 技能页（`skills.js`） | `skill-card` 卡片，按来源分组，「更多」进入技能市场 |
| 列表 → 安装 → 使用 | 列表接口（`/marketplace/agents/list`、`/skills/list`）只回摘要；**安装 = 下载到本机**：取包 / 依赖技能 → 质量与安全检查 → 写入 `<用户>/local/marketplace/…` → 登记 `installs.json`（`marketplace.ts:1318`）；「使用」只读本机（`agents.js:3655` `useAgent`、`:3743` `useSkill`） |
| 内置内容 | 安装包里的 `resources/builtin/marketplace/`（32 个智能体、58 个技能）在启动时复制进同一棵本机目录并登记；Hub 标了 `default_install` 的登录后自动装好（`marketplace.ts:2164`）。所以内置 = 提前装好的平台内容 |
| 停用（2026-10-19 核对） | 每个用户一份停用名单 `cloud/config/component-enabled.json`（`component_enabled.ts`），不分来源，自带的也能停（`ipc/index.ts:4604`：「Builtin and custom both toggleable」），只有主智能体不能停。**停用真实生效**：技能从主智能体提示词的「可用技能」里剔除（`runner.ts:578`）、按需搜索时过滤（`skill-registry.ts:708`）、读它的文件也被拦（`file-tools.ts:255`）；智能体从主智能体的「可用智能体」清单里剔除（`group_chat/bus.ts:9088`）、`dispatch_to` 派不到（`bus.ts:9355`）。现有入口散落在每张卡片的菜单 / 详情里 |
| 自带内容会被自动调用 | 主智能体提示词里列出**所有启用的**智能体与技能（含自带的 32 个智能体、58 个技能），它可以自己挑技能用、自己把任务派给智能体，不需要用户先选或 @ |
| 「自带」有两种（S3 已核实，`specs/008-hub-agent-distribution/spec.md` 第 39–42 行） | ①**随包预置的 Hub 内容**（上面的 32 + 58，可停用）；②**系统内置技能** 8 个（`resources/builtin/system/skills/`：`agent-creator`、`skill-creator`、`coding`、`package-installer` 等），是产品规程文件，单独注入「System skills」块，不是市场内容，不出现在技能页 |

## 3. 规则

**带「待定」的由产品确认；其余为设计默认值，评审时一并确认。** 「v0.4」标注的是相对 v0.3 的调整。

| 编号 | 规则 |
|---|---|
| R1（v0.4） | **智能体首页分三组**：①**主智能体**（cogseed）；②**外接智能体**（Codex / Claude Code 等，保持现状）；③**平台**：全部来自 Hub 分发，**不标来源**。**平台内容统一走 Hub（中扬 2026-10-19 定）**：不再区分「客户端自带」与「Hub 分发」。原随包内置、默认安装的内容，老用户升级后**迁移为「已安装」**，与用户自己装的完全一样（可停用、卸载）；停止随包预装由迁移任务单独跟进（见 [自带内容改走Hub-迁移与离线.md](自带内容改走Hub-迁移与离线.md)）。8 个系统内置技能不进商店、不在页面上展示。**技能首页**：只有平台一组。平台组排序：已安装的 → 还没安装的。**「我的智能体」只放用户自己创建的**，不分组、不再有来源筛选。**「我的技能」是一个网格、不分组**：自定义的在前，本机已有的（客户端 open-tier：外部包与全局文件夹扫描到的技能，只读，只能使用、停用，不能贡献；见 D-09）在后；卡片标「自定义 / 本机已有」，顶部按来源筛选「全部 / 自定义 / 本机已有」（代替分类筛选）。本机已有的在这里管：单个技能在详情里停用；外部包在详情里「移除」（按包，先确认）；顶部说明条有全局文件夹总开关「读取 ~/.claude、~/.codex 的技能」。自建卡片有「贡献」；**「我的」页工具栏有「我的贡献」**（首页工具栏不再放，避免与「我的智能体」并排重复），进入客户端现有的「我的贡献」页（原型照 `hub-contributions.js` `renderMine` 做了可点击版） |
| R2（v0.4） | 详情统一为一种弹窗（照「连接器使用弹窗」）。说明行：平台内容为「分类 · 平台 · 版本」，外接为「分类 · 外接智能体」，自建为「分类 · 我创建的」。底部操作：主按钮「使用」（没装过的平台内容为「安装」）；自建另有「贡献 / 管理 / 停用」；外接另有「管理 / 停用」；**取到本机的平台内容**另有「停用 / 卸载」；**本机已有的技能**：外部包另有「停用 / 移除」（按包，先确认），全局文件夹的只有「停用」，说明行为「分类 · 外部包（仓库）」/「分类 · 来自全局文件夹」；主智能体没有其他操作。停用后卡片变暗、「使用」不可点，仍可点开详情并「启用」 |
| R3（v0.4） | **点卡片 → 详情弹窗；点「使用」→ 直接开始**（卡片和弹窗里的「使用」一样）。弹窗里点「使用智能体 / 使用技能」或点示例，进入现有新任务流程，示例直接发送。已停用时示例和「使用」置灰 |
| R4（v0.4） | 断网 / Hub 不可用：首页顶部提示「暂时无法获取平台内容」+ 重试；**只显示已安装的**，照常可用；「我的」不受影响。**不做离线兜底**（不随包留备用清单）：产品本身要联网使用，服务器故障属运维范畴（中扬 2026-10-19）。未登录不开放平台内容（不为匿名用户单独设计体验） |
| R5（v0.4） | 创建入口**只在「我的」页工具栏**（首页不再放，避免与「我的智能体」重复；与「我的贡献」同理）；创建的进「我的」；**外接的进首页「外接智能体」组**；「我的」为空时有引导 |
| R6 | 分类沿用各自 spec；首页三组和「我的」都按分类与搜索过滤，支持中文输入法 |
| R7（v0.4） | **不展示「N 万人在用」**，本期只采集数据（口径见 §5、D-08）。标签为可选字段：Hub 有就显示 |
| R8 | 新版本、已下架、卸载有依赖、**停用有依赖（D-12）**：规则见 brief；原型已画「有更新 / 更新失败」「停用有依赖」「依赖已停用」，「已下架」「卸载有依赖」未画 |
| R9（v0.4） | **安装 / 使用**：还没装到本机的平台内容，卡片按钮为「**安装**」（详情底部为「安装智能体 / 安装技能」）；点击后变「安装中…」（不可重复点），装好后**留在原处**、提示已安装，按钮变「**使用**」（类似豆包「召唤」→「对话」的区分）。**详情里直接点示例 = 先安装再直接发送，一步完成**（用户已经表明要用）。本机已有的（内置、默认安装、外接、自建、本地）一直是「使用」。底层安装 = 下载到本机并登记（技术上无法免下载，见 brief 第 2 节）。失败时卡片保留、显示「安装失败，可重试」，详情给出原因和「重试」，不破坏已有内容。安全扫描、质量检查要用户确认的情况，沿用现有弹窗 |
| R10（v0.4） | **已安装的智能体 / 已安装的技能**（原「管理」页，改名）：入口在首页工具栏最右「已安装的智能体 · N」/「已安装的技能 · N」，页面标题同名。「**从平台安装的**」一组：列出所有装到本机的平台内容，**包括老用户迁移来的原随包内容（`seed_source: builtin`）和默认安装的（`default_install`）**，不再区分；每行图标、名称、简介、「卸载」和一个启用 / 停用开关；页头「已启用 N / 共 M」；为空时说明「点安装后会出现在这里」；点一行打开同一种详情弹窗。原随包内容迁移后同样列在这里。停用后任务里不再调用、@ 也找不到；卸载后再用会重新获取。**一样东西只放一处**：本机已有的技能（全局文件夹、外部包）是用户自己的，**只在「我的技能」里**，不进本页；页头计数也不含它们。 |

## 5. 落到客户端要改什么

> 依据 2026-10-19 读源码写成；**实际落点与此表的差异见本节末「5.1 实现后的差异」**。

| 改动 | 落点 | 做法 |
|---|---|---|
| 智能体首页三组 | `agents.js`（`groups` 分组处） | 「自定义」组移出首页；「平台」组并入原市场列表的未安装项（复用 `marketplace.listAgents` 的请求与缓存）；去掉「更多」 |
| 技能首页 | `skills.js`、`marketplace.js` | 同上：只有平台组 = 本机已有的平台技能 + 市场未安装项 |

| 「我的」 | `agents.js`、`skills.js` | 只渲染 `custom` 来源；卡片保留现有「贡献」；「我的」页工具栏放「我的贡献」入口，进入 `hub-contributions.js` / `hub-agent-contributions.js` 现有页面；**首页工具栏去掉现有的 `agents-mine-btn`**（`index.html:546`），返回行改为回到「我的」 |
| 安装 / 使用 | `agents.js` `useAgent` / `useSkill`、`marketplace.js` `_mpInstall` | 「安装」= 调用现有 `_mpInstall`（保留安全卡、质量报告；智能体的「将同时安装」确认框是否保留见 D-02），装好后按钮变「使用」；详情里点示例 = `_mpInstall` 成功后接着调用 `useAgent` / `useSkill` 并发送；不新增主进程能力 |
| 已安装页（原管理页） | `agents.js`、`skills.js`、`marketplace_installs.ts` | 列出所有已安装的平台内容（含 `seed_source: 'builtin'` 与 `default_install`，界面统一视为已安装）；开关复用现有 `enabled`，卸载复用 `marketplace.uninstallAgent` / `uninstallSkill`。本机已有的技能不进本页（见「我的技能」行） |
