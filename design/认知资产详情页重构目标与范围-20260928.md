# 认知资产详情页重构：目标与范围

状态：本轮需求与验收范围定义，2026-09-29 按用户补充要求改为全程单列。依据为用户提供的真机截图、当前 `assetDetail()` / `viewExperienceDetail()` 实现及现有用户旅程规格；实际完成情况以代码和真机验证为准。

## 1. 要解决的问题

用户打开一条详情，应能快速回答四个问题：**这条记的是什么、现在会不会被使用、从哪里来、实际用得怎样**，随后才处理编辑、版本和治理。

截图中的正文卡在宽窗下行长过长，整段灰字难以定位要点；开关和按钮集中在标题最右侧，开关的含义要读标题下的长句才能理解；“来历 3”与聚合后的来源展示缺少明确关系；“用过吗”被压成侧栏的一行小字；侧栏的管理卡大片留白，却把重要的版本、使用明细和治理入口藏在折叠里。截图里还出现相似正文连续重复：需区分源数据重复与渲染重复，不能只为视觉整齐而静默删掉用户内容。

本轮目标是把详情页从“把所有字段放上来”改成**以正文阅读和来源核对为主的工作页**。提高首屏可理解性、长内容可读性、操作可预期性，并保留当前真实的证据、版本和使用口径。

## 2. 覆盖范围与边界

| 对象 | 本轮要求 |
| --- | --- |
| 五类正式资产 | `个人信息`、`规则与偏好`、`模板与范例`、`技能与方法`、`事实与知识` 全部使用同一详情骨架；检查每类真实长短内容、空字段和边界字段。代码入口为 `src/renderer/modules/cognition-assets/views.js::assetDetail()`。 |
| 资产状态 | 生效中、已暂停、已归档、已删除及不可操作状态必须有明确呈现；允许的动作与结果保持一致。 |
| 经验详情 | “经验”在“我的认知”里有独立详情，但不是正式资产。`viewExperienceDetail()` 纳入布局、文字层级、组件和窄窗一致性检查；保留经验独有的预期/实际、验证状态和管理语义，不套用正式资产的“被任务用过/模型确认采用”指标。 |
| 其他详情 | 候选、整理任务、大扫除报告不是正式资产详情；本轮不重做其业务流程。共享视觉规范若影响它们，须检查没有退化。 |
| 数据与业务 | 不改变资产类型、授权、读写通道、版本规则、证据解析、来源链接和计数公式。`被任务用过`沿用现有去重口径；`模型确认采用`只认 `applied` 回执，不能把带入、读取或派发写成采用。 |

既有 `specs/018-用户旅程雕刻/spec.md` 的“三问”继续作为用户目标；其中“首屏只有三段”不再限制本轮卡片数量和左右排布。旧文档提到的敏感档位已从现行机制删除，本轮不恢复该字段。若旧版式描述与此文档冲突，按本轮用户截图提出的重构目标处理；业务事实仍以当前代码和数据合同为准。

## 3. 页面结构与信息层级

### 3.1 阅读顺序

1. **页头：识别与当前状态。** 返回列表、资产类型、状态、标题、可见的启用说明和首要操作。状态文字紧邻开关；标题下只留一条简短的当前影响说明，避免长政策句抢正文位置。正在使用的版本号可作为轻量元信息，但版本差异仍归版本区。
2. **主内容：这条资产说了什么。** 用明确的“内容”标题展示当前在用版全文。正文是页面视觉主角，不与状态说明、来源 chip 混在同一卡。当前版若有适用/禁用场景，以独立的“适用边界”行呈现并标明属于当前版；缺失时不得暗示“适用于所有场景”。
3. **来源与使用：能否核对。** 来源按对话/任务复盘等现有分组展示，能回看的可点击，失效的说明不可用；使用情况分别列出“被任务用过”和“模型确认采用”，同时给最近一次可核对记录。来源数应说明是原始记录数还是聚合后的条目数。
4. **深入信息：按需展开。** 使用明细、采用记录、排序依据、版本对比、标签、归并和生命周期台账保留，但以清楚的分组和入口呈现。折叠标题说明其中内容，避免让“详情与历史”成为无法预判的杂物箱。
5. **治理操作：靠近相关信息。** 编辑、用到当前对话、启停等常用动作易找；删除和彻底清除单独归为危险操作，保持现有确认与恢复语义。

### 3.2 宽窗与窄窗

- 宽窗和窄窗都采用**单列、上下顺序**；内容、来历、使用、版本、管理各占一整行，不在右侧另设独立卡片。整个详情区设合理最大宽度，正文保持约 760–880 px 的阅读宽度，不随 2K/3K 窗口无限拉长。
- 每个区块只按内容决定高度，来源与生命周期台账都在同一阅读宽度里展示，避免窄侧栏挤碎文字或横向溢出。
- 窄窗只收紧内边距、允许标题操作换行，不改变区块顺序：页头 → 内容及适用边界 → 来源 → 使用情况 → 使用与版本 → 管理。640 px 窄窗无横向滚动、无按钮相互覆盖。
- 页面区块采用稳定 DOM 顺序，键盘焦点顺序与视觉阅读顺序一致。

## 4. 核心内容的展示规则

| 类型 | 首先看清的内容 | 补充信息的安排 |
| --- | --- | --- |
| 个人信息 | 当前记住的个人事实或偏好原文；不把标题当成正文重复。 | 有明确来源、范围和版本时给核对入口；无时间依据不自行声称“仍然有效”。 |
| 规则与偏好 | 规则本身和适用/禁用条件分开显示。 | 条件来自现有字段，不能从自由文本臆造规则边界。 |
| 模板与范例 | 保留范例的换行、缩进、序号及代码样式的原始结构。 | 来源和版本可回看；不为了卡片整齐截断范例正文。 |
| 技能与方法 | 方法正文适合逐步阅读，保留原有步骤和分段。 | 有适用条件时显示；不要从正文自动推断新步骤或执行能力。 |
| 事实与知识 | 清楚呈现事实陈述及其可追溯来源。 | 来源缺失、失效、相互重复都如实标识，不把“有引用”表述成“事实已验证”。 |

- 正文默认完整可读，保留换行与段落，增强正文与辅助文字的对比；标题、正文、注释使用清晰的三级字体层级。长词、文件名和路径允许换行，不撑破卡片。
- 对超长正文提供可定位的段落结构；如源数据本身只有一整段，不自动拆写或改写含义。截图中的重复句先核查数据与渲染；若是源数据重复，给用户明确的编辑路径；若是渲染重复，修渲染。
- 加载中、确实为空、读取失败分别表达；尤其使用回执尚未加载时不能显示成“0 次”。来源不可用时说明“记录不可回看”，不显示裸内部 ID。
- 多条来源允许视觉聚合，但保留原始条数和逐条回看能力；聚合后的 `×N` 与来源总数必须可以解释。

## 5. 交互与可用性

- **状态操作**：开关要有可见标签和简短后果说明；启停后状态、文案与可用操作同步更新。暂停、归档、删除页不出现无法完成的操作。
- **编辑**：标题与正文编辑清楚说明“保存为新版本”；取消不提交，异步刷新不丢输入和焦点。适用范围等高级字段继续按当前权限与版本规则处理。
- **使用与来源**：来源 chip、最近一次使用和版本记录有清楚的可点击样式、键盘操作和返回路径。带入当前对话后的反馈应说明作用于哪个对话、之后如何撤销。
- **折叠与菜单**：展开状态在页面异步补数时尽量保留；菜单能用键盘打开、关闭并返回触发点；隐藏的危险操作不能因误触直接执行。版本区的内部滚动和整页滚动不应突然跳顶。
- **反馈**：保存、启停、删除、恢复、归并、来源跳转失败等都给明确结果；长操作有进行中状态，失败后可重试。空数据给下一步，不放一块没有意义的空卡。
- **可访问性与本地化**：标题层级、地标、按钮名称、焦点环、触控面积、色彩对比和减少动态效果符合现有组件要求；所有新增可见文案进入四语言资源。颜色不单独承担状态含义。

## 6. 视觉与组件规范

- 使用现有设计 token 控制颜色、字体、间距、圆角、边框和响应式断点；统一卡片内边距、区块间距、标题行和元信息行。不另造一套页面私有按钮、开关、标签或弹层。
- 叶子控件复用共享 `uiButton`、`uiSwitch`、`uiTag`、`uiEmptyState` 等；卡片和披露结构优先采用现有共享能力或已登记的认知资产页内组合。新增结构先对照 `docs/renderer-structural-registry.md` 的 `COG-PV-010`，避免同类详情各写一种视觉与键盘行为。
- 主操作、次操作和危险操作在颜色、位置与文字上保持一致；“生效中”“已实证”“模型确认采用”是不同语义，不能用同一种绿色章混成一个结论。
- 正文、辅助说明、时间与技术信息的对比度递减，但辅助信息仍应可读；信息较密的版本/台账使用明确的字段标签和对齐，不用一长串点号串联所有事实。

## 7. 优先级与完成判据

| 优先级 | 优化重点 | 完成判据 |
| --- | --- | --- |
| P0 | 五类正式资产共用清晰骨架；正文可读；当前状态、来源、使用/采用口径准确；危险操作保留护栏。 | 首屏可找到“是什么、是否生效、从哪来、用过吗”；全文不截断；来源与计数与既有数据口径一致；所有原有动作和版本信息仍能到达。 |
| P1 | 宽/窄窗布局、编辑与折叠状态、空/加载/错误反馈、键盘和焦点。 | 1440/1100/640 px 无横向溢出；读屏与 Tab 顺序合理；异步刷新不丢编辑草稿、滚动及关键展开状态；状态切换后动作准确。 |
| P2 | 五类内容的阅读细节、经验详情视觉一致性、微文案与密度调整。 | 长标题、长正文、多来源、无来源、零使用、失效来源均能稳定阅读；经验详情保持独立业务语义但视觉语言一致。 |

实施完成后，应以五类资产的代表数据和各状态做真实页面走查，核对桌面与窄窗、来源回跳、编辑保存新版本、启停、删除/恢复、使用回执以及四语言文案。静态截图或组件预览只能证明外观，不能替代真机中的数据和交互验证。
