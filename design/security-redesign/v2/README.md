## 这一版的范围（评审已定）

v1 收到「太繁琐」的反馈，v2 第一轮把 hero 也一起简化了（去评分环、来源下沉）。
**评审否决了那部分**：hero 原样保留。所以：

- **hero 逐条对齐生产**（`style.css:27409-27458`）：评分环 + 标题 + 状态胶囊 +
  描述 + 5 个来源字段 + 三个按钮 + 降级提示条。几何、字号、圆角、边框色照抄生产值，
  不套用我自己的排版偏好。
- **简化只作用于 hero 以下**：原来铺在页面上的能力覆盖网格、组合风险区块、
  检查记录表 + 统计行 + 分段控件，收成三行可展开的「防护项」。

主屏实测 **1180×608px**（拦截态，全部收起）。

## hero 保留带来的两处连带调整

保留 hero 不是没有代价的，有两处必须跟着改，否则会变成新的重复：

1. **删掉 v2 原有的「检查来源与完整性」行。** hero 已经展示扫描器 / 引擎 / 规则包 /
   规则条数 / 完整性，再留一行就是同一信息两处出现——正是我原先批评生产版的问题。
   防护项从 4 行降到 3 行。
2. **页面容器从 720px 放宽到 940px。** 720px 下 5 个来源字段会换行、按钮会挤压正文，
   与生产形态不符。放宽后 hero 的排版与截图一致。

另外**恢复**了「检查指定技能…」的选择器交互（生产有，属于 hero 的一部分）。

## 改了什么（仅 hero 以下）

| | 生产版 | v2 |
| --- | --- | --- |
| hero | — | **原样保留** |
| 检测能力覆盖 | 独立区块：区块头 + 规则标签行 + 外部工具标签 + 16 格网格（13 格是「可用」） | 折进「检测能力」行；默认只列需要注意的 3 项 |

| 主屏可见区块 | 4 个（hero + 覆盖 + 组合 + 记录） | **2 个**（hero + 防护项） |

保留 hero 后仍有这些简化生效：

- **同一组数字不再出现两遍**：生产把「技能总数 7 · 已通过 2 · …」既渲染成一行文字、
  又渲染成紧随其后的分段控件。v2 只留分段控件，并为屏幕阅读器保留同一句话（视觉隐藏）。
- **能力网格注意力倒置**：折叠态只列「需要注意」的项并高亮，健康项收进「展开全部 16 项」。
- **记录表 4 列封顶**：生产的 6 列在窄栏会把右侧操作按钮挤出可视区。
- **状态胶囊只出现在告警行**：生产的表格里每行都有胶囊，v2 只在需要处理/需要留意的行显示。

## 行怎么做、以及要共享层配合的一处改动

行用页面本地 `<details>`——**原生语义，页面不写任何 focus trap 或 keydown 逻辑**。

共享的 `uiAccordion(...)`（`ui-structure.js:50`）形状正确，但只接受
`items: [{title, meta, bodyHtml}]`，**`meta` 是转义纯文本，没有 per-item tone**，
健康行与告警行无法区分，所以本版没有用它。

**落地前应给 `uiAccordion` 加 per-item `tone`（及可选 `icon`）**，然后把行改为复用共享缝、
删掉页面本地实现。这是组件契约变更，需要组件预览页补状态矩阵。
（先例：`KB-PV-001` 明确不把 `uiUserMenu*` 当通用菜单，所以我没有自己造菜单。）

## 内联 SVG 回来了

保留评分环意味着本版的 `draft.js` 有 **1 处内联 `<svg>`**（`scoreRing`），
属数据可视化而非图标：半径/描边/`stroke-dashoffset` 都由分数算出，静态 path 无法表达。
沿用生产登记 **`SEC-PV-001-SVG`**（`docs/renderer-structural-registry.md`）。
第一轮简化版曾把这个例外降到 0，现在回到 1。

### 重新生成

```bash
node design/security-redesign/v2/build.mjs
python3 design/security-redesign/v2/trim.py
```

**全程无窗口**：`build.mjs` 是纯 Node，只调用系统 Chrome 的 `--headless=new`，
不启动 Electron。v1 的工装用了 Electron `show: true` 窗口（放在屏外但仍会出现 Dock
图标并有抢焦点风险），**已不再使用**。

两个已踩过的坑写在 `build.mjs` 注释里：
1. 本环境下 Chrome 写出截图后**不会自行退出**，不能等 `close` 事件——
   改为轮询产物文件大小稳定后 `SIGKILL`。
2. `--dump-dom` 在 `--headless=new` 下会挂死，页面高度改用
   「高窗口渲染 + `trim.py` 按底色裁掉底部空白」得到。

## 尚未解决 / 需要你定

- **`uiSegmentedControl` 不携带 value**（v1 已记录，本版未解决）。它只在内部用 `value`
  比较选中态，从不写进 DOM（`ui-segmented-control.js:39-40`），页面只能靠**本地化标签
  文本反查取值**（两套词汇、9+ 个标签、兜底 `'all'`）。翻译碰撞会静默选错筛选器。
  修法在共享层加 `data-value`，属组件契约变更、会波及其他调用方。**这不是布局问题。**
- **共享层缺内联 banner 缝**。`uiAlert` 是模态对话框，不能当内联提示用；
  提示条仍是页面本地组合。
- **新增文案没有 i18n 键**。`draft.js` 的 `DX` 对象是临时措辞（如「防护项」「技能检查」），
  落地时必须补 `settings.security.*`。
- **`social-data` 行的降级说明会被省略号截断**（列宽有限）。信息在详情抽屉里不丢，
  不接受的话需要再砍一列或缩短该文案。
- **hero 标题在拦截态仍读作「系统保护已开启 · 有技能被拦截」**——同一句里既说保护正常
  又说有东西被拦。我原先改成「1 个技能被拦截」，但既然要求 hero 原样保留，我改回了生产
  文案。这条要不要动，由你定。
