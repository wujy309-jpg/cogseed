# 本体总览与多领域分类关系设计 v0.1

- 日期：2026-09-27
- 状态：产品设计草案；本轮按用户明确方向落地首个页面切片
- 范围：认知资产中的「本体」入口、总览、个人本体、事项本体、分类与关系浏览，以及认知树树干命名
- 兼容约束：现有个人本体分组、角色模板、正式认知资产、来源投影和 IPC 数据契约保持不变

## 1. 设计目标

把原来只承载个人资料的「关于我」入口提升为跨领域的「本体」工作区。用户从同一个入口认识系统保存了哪些人、事、类目和关系，并能继续进入当前已具备真实数据和操作能力的页面。

顶层页签与认知树树干都叫「本体」。点击后进入「本体总览」；「个人本体」是本体中的一个领域，不再代表本体整体。

## 2. 概念层级

本方案把四个维度分开，避免把领域、分类、条目类型和关系混成一棵目录：

| 维度 | 回答的问题 | 首批示例 |
|---|---|---|
| 本体领域 | 这片知识描述什么领域？ | 个人、事项 |
| 分类与类型 | 领域里有哪些类目和字段？ | 身份与角色、项目、任务、事件、目标 |
| 条目 | 具体描述了谁或什么？ | 一条个人事实、一个项目事实、一个任务事实 |
| 认知形态 | 这条内容以什么形式起作用？ | 事实、规则、方法、模板 |
| 关系 | 条目之间如何连接？ | 负责、包含、依赖、细化、相关、冲突 |

个人、事项是领域；事实、规则、方法、模板是内容形态。一个项目条目可以同时关联事实、规则和方法，内容形态因此作为筛选标记，不与领域争同一层级。

## 3. 信息架构

```text
本体
├─ 本体总览
├─ 个人本体
│  ├─ 事实与条目
│  ├─ 分类与字段
│  └─ 关系与规则
├─ 事项本体
│  ├─ 项目
│  ├─ 任务
│  ├─ 事件
│  ├─ 目标与决策
│  └─ 事实与知识
├─ 分类体系
└─ 关系网络
```

「事项本体」中的项目、任务、事件、目标、决策是可编辑实体；正式事实资产继续作为独立来源条目展示，不会自动转换成图谱实体。人物、组织、产品、工具、文档、地点属于「对象与资源」；术语、方法和规则属于「概念本体」。所有领域共享分类层级与关系网络。

个人本体沿用现有结构：身份与角色、工作方式、沟通与交互偏好、目标与边界、关系与环境。未归类内容保留在「其他沉淀」，不隐藏、不自动改写。

## 4. 页面布局

### 4.1 本体总览

- 页头：标题「本体总览」，说明本体会整理个人、事项、分类和关系。
- 左侧导航：本体总览、个人本体、事项本体、分类与字段、关系网络；进入个人本体后保留现有词汇/事实/规则工作区。
- 主区：个人本体、事项本体、对象与资源、概念本体、分类体系、关系网络六张数据驱动的入口卡片，展示真实数量、用途和下一步。
- 关系预览：展示明确保存的关系数量和起点、谓词、终点；点击进入关系网络。
- 状态：加载、空数据、读取失败分别表达；内置分类是真正可用的系统分类，实体、关系和来源引用读取真实持久化数据。

### 4.2 个人本体

个人资料仍由既有画像资产、本体分组和角色模板管理。现有「词汇／事实／规则」后台结构对用户翻译为「分类与字段／事实与条目／关系与规则」，不更改 T/A/R 盒、分组文件、角色模板和已存在的编辑行为。图谱关系可以连接内置的虚拟端点「我」，无需建立重复的“本人”实体。

正式认知资产投影值继续显示来源，并跳到原资产修改；图谱实体和关系只保存 `{kind, id}` 来源引用，不复制个人资料、正式资产或候选正文。来源不可见时保留引用并允许用户移除。

### 4.3 事项本体

事项实体可创建、编辑、归档、恢复和删除。每个实体归属一个分类，可填写分类定义的字段、说明，并关联正式资产或候选 ID。事项页同时呈现事实类正式资产，提供来源条目跳转。

创建、重命名、删除事项分类和字段时检查父子关系、已有实体引用和字段值；有关联时阻止可能造成孤儿或数据丢失的操作。实体仍有关系时禁止硬删除，用户需先删除相关关系。

### 4.4 分类与关系

- 分类体系提供个人、事项、对象与资源、概念四个视角；个人分类读取现有数据，其他领域使用内置分类并支持用户增加、编辑、建立层级和删除自定义分类。
- 分类字段支持文本、日期和数值。新增实体时按分类展示字段；字段仍被实体使用时禁止删除或改名。
- 关系端点支持虚拟的「我」和任一本体实体，用户可自定义关系名称、说明和来源引用；禁止自环和重复关系。归档实体保留历史关系，不能再作为新关系端点。
- 关系网络合并展示图谱关系、个人本体中明确录入的 `A → B` 和现有正式资产关系。每条边展示起点、谓词、终点、来源和可用操作，不展示内部 ID，也不推断关系。
- 关系以可读的三段式边列表呈现，实体详情能看到关联数量；不依赖文本相似度建立连接。

## 5. 认知树

- 树干短标签统一为「本体」，树干和对应光斑进入同一个「本体总览」路由。
- 树冠仍表达真实使用过的正式认知资产；枝端仍表达当前正式资产类别；根部和土壤仍进入待处理与系统活动。
- 资产类型如事实、规则、方法、模板继续作为资产浏览维度，不把它们误作个人/事项等本体领域。

## 6. 命名规则

| 界面位置 | 中文名称 |
|---|---|
| 顶层页签、树干、工作区入口 | 本体 |
| 总览页标题 | 本体总览 |
| 个人领域 | 个人本体 |
| 项目/任务/事件等领域 | 事项本体 |
| 正式资产类型 `personal` | 个人信息 |
| 本体数据浏览 | 分类与字段、事实与条目、关系与规则 |

这样「本体」表示总空间，「个人本体」表示其一个领域，「个人信息」仍可在资产类型选择器中描述一条资产的内容类型。

## 7. 持久化和 IPC 契约

- 图谱数据存于 `cloud/cognition/ontology-graph.json`，通过 `userOntologyGraphFile(uid)` 定址、文件锁串行化读改写、同目录原子写入。
- 文件含 `schemaVersion: 1`、`ownerId`、自定义 `categories[]`、`entities[]`、`relations[]`。用户首次写入时才创建文件；系统内置分类从代码生成，不复制进用户文件。
- 实体拥有稳定随机 ID、领域、分类 ID、名称、说明、按字段 ID 保存的属性、状态、来源引用和时间戳。关系拥有稳定 ID、两个端点、谓词、说明、来源引用和时间戳。
- 关系端点是 `{kind:"self"}` 或 `{kind:"entity", id}`。来源只接受 `{kind:"asset"|"candidate", id}`；不会复制候选的 `summary/judgment/value`、个人画像正文或正式资产正文。
- 每次读写校验所有权、版本、ID、领域、字段、端点、重复关系和文件大小。损坏或未来版本文件会报错，不会当空数据覆盖。
- IPC 只从已认证上下文取得 `userId`，不接受渲染层传来的用户路径或 `userId`。写入成功后广播 `cognition:changed` 的 `ontology-graph` 集合，其他窗口按路由刷新图谱。
- 删除分类需无实体和子分类；删除实体需无关系；移除正在使用的字段被拒绝。归档保留实体及关系历史。

## 8. 验收口径

1. 顶层页签与树干均显示「本体」，进入同一个本体总览。
2. 总览能进入个人本体、事项本体、对象与资源、概念本体、分类与字段、关系网络。
3. 空图谱会显示内置分类和创建入口；数据读取失败与空态明确区分，不覆盖损坏数据。
4. 实体、分类、字段和关系能持久创建、读取、修改、归档或按引用保护规则删除。
5. 图谱来源只保存正式资产或候选 ID；打开来源回到既有条目，不复制正文或改变资产用途/准入策略。
6. 个人资料、候选格式、正式资产确认和整理设置的既有数据契约不变。
