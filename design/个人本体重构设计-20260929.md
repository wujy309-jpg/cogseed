# 个人本体重构设计与验收 — 2026-09-29

范围：本体模块中的「个人本体」部分整体重构（数据模型、后端业务逻辑、IPC、前端全部界面）。事项本体/对象与资源/概念本体/关系网络等其余本体域不在本次范围，仅做数据源适配。

## 一、为什么重构（病根）

1. **markdown 当数据库**：字段值是文本行，元数据全靠行内标记（`@kind:`/`@asof:`/`@restricted`）。标记缺省 = 未分类——「关系与规则」页的 操作规则/偏好/约束 筛选全空、条目不可编辑（子安 09-29 红笔批注），都是这个存储模型的必然结果。
2. **文本寻址**：改/删一条值按「值文本」匹配，同文本两行只能一起动。
3. **前端 1+N 次往返**：三盒数据逐组拉 `fields.list` + `groups.read` 再拼装。
4. **导出/导入指向已退役的记忆文件**（USER.md/MEMORY.md），不是个人本体自己的数据。

## 二、新架构

### 数据模型（po/model.ts）
JSON 单文档 `<uid>/cloud/cognition/personal-ontology.json`（与 assets.json / ontology-graph.json 同目录、参与云同步、schemaVersion=2）：

- `PoGroup` 分组（`kind: 'user' | 'template'`；模板组带 templateId/templateVersion）
- `PoField` 字段（`origin: 'schema' | 'user'`；模板组分节承载在 `section` 列）
- `PoValue` 字段值（来源/时间锚 asOf/核实/规则分类 ruleKind/敏感性 restricted/资产归属 assetId 全部是一等列，带稳定 id）
- `PoEntry` 流水（记一笔）
- `trash` 回收站（被删分组整状态可恢复）；历史快照/摘要台账迁 `cloud/cognition/po-history/`

### 存储内核（po/store.ts）
文档级 fileEditLock 串行化；`editPoDoc` 统一「改前快照 → 落盘 → 渲染同步 → kb 索引钩子 → 认知写通知」。`.personal_ontology_groups/` 下的 md 文件从「数据库」降级为**写时渲染的视图副本**，仅供 kb 检索索引、transcript 术语桥与人类调试——这三个消费方零改动。

### 兼容面
`personal_ontology_groups.ts` / `personal_ontology_template_files.ts` / `personal_ontology_migration.ts` 保留全部导出名（注入链 facts/taxonomy/rules、矛盾检测、候选确认、contract、@ 引用、opaque `po1` ref 都不用改）；方言纯函数收编进 `po/dialect.ts` 唯一定义。

### v1 迁移（po/migrate.ts）
一次性导入：组 id/值/全部元数据原样保留；`.history` 旧 md 快照逐版转 JSON；孤儿历史组复活进回收站；阶段 B 遗留模板组并进模板组；v1 目录整体备份到 local 后台账移除。

### 新 IPC（`po.*`，28 个通道）
`po.snapshot` 一次交付整棵结构；全 id 寻址的 fields/values/entries 增删改；规则分类**直接设档**（不是循环 toggle）；模板安装/卸载/归档；历史；`po.data.export/importPreview/importApply`（个人本体自己的 markdown，可回灌）。旧 `personalOntology.*` 通道原样保留。

## 三、新界面（personal-ontology.js 重构）

- 个人本体三页：**事实与条目 / 规则 / 分组与模板**（User Story 词形，不再暴露 T-box/A-box/R-box 治理概念；「分类与字段」独立页并入分组与模板）。
- 事实页：待确认候选横幅（收下时选去向 + 跳过）、分组筛选 + 搜索、按组分节的值列表、每条值「⋯」菜单（编辑/规则分类直接设档/仅自己可见/核实/删除）；模板组以分节表单呈现；资产投影行只读 + 查看来源资产；画像条目分区只读。
- 规则页：全部/操作规则/偏好/约束/**未分类** 筛选 chips 带计数（修复分类失效）；归属面包屑；来自认知资产的规则单列。
- 分组与模板：分组卡（字段清单/计数/历史/回收站恢复）+ 角色模板行 + 模板库。
- 编辑全部走 uiModal 表单（文本 + 时间锚三态 + 规则分类），不再藏在值行展开区。
- 按钮全部走 `_button`/`_iconButton`/`uiCheckbox` 共享原语；select 有统一 `po2-select` 样式。

## 五、已知语义变化（有意为之）

1. 规则分类是值的直接属性，编辑弹层直接设档；存量未分类值在规则页「未分类」chip 下可见，可逐条归类。
2. 删除分组进回收站（整状态恢复），不再是「只靠 .history 兜底」。
3. 导出/导入是个人本体自身的 markdown（`## 分组名` + 双区方言，规则分类/时间锚/敏感性随行保留），不再指向退役的 USER.md/MEMORY.md 导出。
4. 模板归档恢复改为**原样恢复**（结构以归档为准），新版本补坑交给 install 后的 reconcile——与 v1 语义一致，实现上消除了「恢复即已迁移」的假象。
5. 迁移 apply 的「只差元信息行」情形合并为 `ledger_repaired`（零内容改动、不留备份、只抬版本列）。
