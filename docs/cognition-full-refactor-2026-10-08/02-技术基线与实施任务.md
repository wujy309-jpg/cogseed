## 3. 工程规则

- 先阅读根 `AGENTS.md`。Electron 主进程 TypeScript；Renderer classic JavaScript，无 JSX／bundler／新 HTTP 服务。通信仅通过 `window.cogseed.{invoke,stream}` 的 IPC allow-list。
- 新依赖先讨论，既有依赖和解析基础优先复用。业务在 features，IPC 只校验与转发，模型适配层不直读写业务主档。
- 共享存储、路径、锁、原子提交、版本日志、隐私与恢复不能绕过；用户数据始终在现有用户域，不能写开发交接包／仓库。
- 根 `AGENTS.md` 要求可见组件修改遵循 `.agents/skills/cogseed-component-change/SKILL.md`、`docs/renderer-structural-registry.md`，优先复用 uiButton、uiInput、uiModal、uiTabs 等共享 API。不把 HTML 裸控件、图标、色值、焦点机制照搬到 Renderer，不提高守卫基线绕过检查。
- 需要新增页内结构而登记为 Proposed 时，不能伪称已获组件所有者批准；先完成可通过共享 API 的范围，记录必要的外部批准和受影响项。当前用户已授权产品页面实施，不自动等于组件所有者的特殊审批。
- 中文文档，UI 四语翻译动态刷新，图标走 `icons.js`，层级走设计 token，输入快捷键遵守 IME。
- 模型输出契约改动同步 prompt、解析器、DTO、真实形状 fixture、迁移和消费者。提示词不写品牌、真实 OS 路径或硬编码工具目录。
- 来源不可用、失败、未知、未保存和部分成功都对应真实状态。检索、绑定、消费与效果分开，不补造回执。

## 4. 独立环境启动

这个新目录已建成 Git worktree；本次不装依赖、不启动应用、不修改真实数据。开始开发时先检查自己的 node_modules 与已有运行条件，按仓库 `package-lock.json` 和 `scripts/ensure-dev-dependencies.cjs` 准备依赖，例如在本目录执行 `npm ci`。这是接手智能体的启动任务，不需用户代办。

不软链接父目录 node_modules：仓库测试会处理 SQLite ABI，共享安装可能影响父实例。不要运行父目录 stop/restart。测试环境使用隔离用户数据和合成样例；真实用户账本的内容批量整理、永久删除和扩大授权不是交接阶段的默认动作。

按独立目录 `./run.sh` 启动，完成后在该目录运行 `scripts/restart-cogseed.sh`；确认只作用该 worktree，并看实际 launcher／runtime 日志。不要为验收自行修改用户全局配置、模型凭证或权限。
