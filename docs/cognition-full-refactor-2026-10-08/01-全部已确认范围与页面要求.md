# 全部已确认范围与页面要求

**这次全部实现：五个页面的收敛重构，少而准确的认知形成，本体与认知资产统一管理，以及后续任务正确使用。**

## 1. 已确定的决定

1. 保留原应用的全局侧栏、浅绿白色风格与主要布局；不要另造应用外壳。正式页面按冻结 HTML 替换。
2. 顶部只保留认知树、我的认知、本体、系统活动、资产设置。删除独立“待我处理”页；其治理动作并入系统活动的需要关注。
3. 认知、对象、事实、定义、来源和变化使用紧凑列表，点击进入详情子页面，返回保留查找、筛选与位置。删除同页侧边详情布局。
4. 按当前回滚后的详情实现：正文、范围、状态、来源、版本及明确的修改操作。纯文本直接编辑方案已经撤回，不能恢复。
5. 按钮使用“手动添加”，不使用“记一条”。现有聊天继续是任务入口，不新增“任务对话”页面。
6. 本体保留目录、跨内容搜索、概览／内容／图谱、三盒、对象信息／关系／规则／采用记录、时间查询、来源版本、创建编辑、引用、导入导出、身份合并与恢复等有效能力。
7. 删除本体整体暂停的按钮、筛选、状态命令与对应后端分支。具体条目／对象的停用及高级夜间发现暂停保留。
8. KSTAR 本轮双向隔离，让它在自身范围运行；不接入认知生产、治理和使用。资产设置不显示其卡片、隔离说明或启用开关。历史来源不得抹去。
9. 系统活动只显示已经严格筛选的认知变化及处理结果。全量对话历史留在原聊天，不搬入活动，也不以“已跳过”灌满已处理。
10. 来源、候选、正式内容、版本、权限、使用和恢复共用一个治理体系；不能形成可竞争的资产／本体正文与审批池。

## 2. 五个页面全部实现

| 页面 | 正式行为 |
|---|---|
| 认知树 | 从同一正式内容和变化读模型构造。分类、本体、需要关注及活动入口跳转准确。点位／数量不把读取当成采用或效果，不展示 KSTAR 新生产分支。 |
| 我的认知 | 紧凑主题／类型列表，搜索正文、标题和范围，显示必要状态。手动添加、导入、唯一存量整理入口、正文详情、编辑、范围调整、逐条停用恢复、来源、版本、使用授权都真实可用。 |
| 本体 | 本体目录与跨内容搜索 → 模块概览／内容／关系图谱 → 具体定义、对象、事实及规则详情。三盒中文表达，人物同名保持独立 ID；多值并存；明确引用；图谱与列表同源。 |
| 系统活动 | 默认需要关注，另有已处理。类型包括新增、补充、纠正、现实变化、冲突、整理。详情显示理由、变化前后、依据、影响及结果，直接接受、修改后保存、拒绝、稍后处理和失败重试。没有独立待处理跳转。 |
| 资产设置 | 说明默认夜间发现与严格选择、后续使用授权、唯一已有内容整理入口；高级暂停和隐私／恢复后果清楚。取消日常手动来源管理、调度时间和提取／定期检查混合控制，不展示 KSTAR。 |

列表与详情使用真实数据，完整状态至少包含加载、空、搜索无结果、读取失败、保存失败、部分完成、基线更新、权限受限、来源不可用。UI 不把失败显示为空或成功。

HTML 的演示数据、Blob 导出示例、reset 按钮及“聊天使用示例”不搬进正式页面。正式聊天使用接入既有 AI 对话。图谱不照抄硬编码对象、固定位置或日期；依据真实查询和准入生成。

## 3. 夜间筛选：完整后端工作

新增／更新的对话 → 内部增量排队 → 粗筛 → 价值判断 → 精筛提取 → 对照已有认知去重核对 → 少量需要关注 → 用户确认 → 正式认知。

- 默认夜间自动执行，使用本地时区。用户不管理来源、队列或日常调度。既有明确暂停／隐私授权不能被默认值无声覆盖。
- 空内容、寒暄、简单一次性问答、当前任务要求、假设、中间试错及被否定的旧说法不产生认知待办。
- 长度和多次迭代只是潜力信号，必须确有稳定、准确、可复用、依据明确且范围清楚的结论。长对话没有成果也忽略。
- “十不存一”是质量方向，不设固定百分比配额，不凑数量。统计会话通过率、有效建议率、重复率及拒绝原因；统计不泄露原文。
- 短但明确的长期要求不能按长度排除；用户明确说记住走即时保存／必要澄清，不等待夜间，不再重复审核。
- 保存增量水位、稳定消息快照、处理版本与幂等身份；活跃对话延后。失败不推进成功水位，确实忽略可记录内部水位，避免每天重复扫描。
- 同一变化的多个依据聚合一项；相同内容追加依据而非新增近义资产。旧证据拒绝后重跑不重提；新增实质证据才重新判断。
- 自动来源只产生建议，不自动批准；目标版本变化重新核对，不覆盖新版本。不把模型类型建议当用户明确归属。
- 未筛选和筛选失败的后台任务不大量占用需要关注。有限后台重试；已筛出的有价值建议保存失败才保留相应事项。持续故障可有必要反馈。
- 应用未运行、休眠或离线时不假装完成；恢复可运行后续办。无需新增常驻守护、定时唤醒或系统 cron 才算本轮达成。
- 新默认不自动回扫全部历史。原聊天中已存在的主动整理能力按同一严格提取与治理承接，不新增全量活动来源管理页。

## 4. 保存、治理与本体统一

- 明确且授权充分的保存真实落盘、回读并链接准确记录；同一请求幂等，不重复。含歧义、同名、冲突或范围不足时只澄清必要部分。
- 同一内容可有资产投影、本体视图和图谱，但共用稳定身份、正文、范围、来源、状态和版本。任一入口改动，其他入口与后续使用同步。
- 概念类型、属性、具体对象、关系和规则不能混成同一节点；模板／方法保留完整正文，不强制每句话拆一条，也不强制一切成为图节点。
- 建议必须携带来源、原文依据、目标、基线和影响；新增、补充、现实变化、历史纠正、冲突各有处理语义。
- 现实变化按新有效期增加版本；历史纠正作用于对应区间并保留原记录，不覆盖今天的事实或篡改原版本。
- 多接收人可以同时成立，单值关系有效期重叠才需核对。同名不同部门不能自动合并；身份合并明确确认、展示影响并支持有边界的恢复。
- 图谱三个层次：本体之间的明确引用，模块内部的概念／对象关系，某对象邻近关系。支持关系筛选、日期、缩放、节点／边详情和返回状态。
- 图谱、列表和任务读取采用同一权限、状态、范围、时间及版本过滤；没有证据不连线，不能用旧引用绕过当前失权。

## 5. 导入、存量与恢复

- 导入明确目标：可复用模板、补充项目／对象资料或仅本次阅读。上传不等于全部长期保存授权。
- TXT／Markdown、已有 PDF／DOCX 支持、正式本体导入导出分别承接；不以 HTML 的演示 JSON 降级正式能力，也不假装支持未选定的 OWL／RDF 引擎。
- 原文与拟议内容分开；预览、选择、取消、失败、部分成功和只重试失败项有真实结果。排除实例姓名和临时时间的错误泛化。
- 存量内容逐项判断重复、混写、范围不清和临时项，预览合并、拆分、范围调整及恢复。保留来源、独立要求和原权限；不静默清空真实资产。
- 对旧本体整体暂停状态先清点迁移影响，删除运行状态与接口时不能静默扩大既有内容的可用性；给出兼容迁移、备份和恢复证据。内部映射到保留的逐条准入机制，具体实现由工程师审计后决定。
- 旧候选、弱观察、经验、历史审批及旧路由安全承接，不制造第二份正文或长期竞争权威。旧待处理深链转到同一系统活动详情，仅保留必要兼容，不继续渲染旧页。
- 迁移可重入、幂等、并发可保护、坏档可报告、失败可恢复。结构迁移与内容语义整理分开，不用迁移偷偷改写内容。

## 6. 后续任务使用全部接通

- 复用现有查阅、明确选用、默认带入的不同准入。已保存不等于自动用于所有任务，默认使用仍满足相关性、授权、范围、状态和有效时间。
- “这次用文字／只发王芳”只影响本次，不修改以后默认；明确“以后也这样”才改长期内容。强制要求冲突／条件未知先说明，不静默绕过。
- 内容纠正／更新后新任务读取新版；旧任务继续显示当时依据、确切版本和只读详情，同时受当前来源权限约束。
- 查询、绑定、投影、实际采用、执行及效果分别记账；保留真实回执和纠正路径。读取次数不是质量或效果证据，不伪造两周观察数据。

## 7. KSTAR 隔离

审计并阻断认知资产与 KSTAR 的双向读取、写入、候选、直写 active 经验、自动晋升、前端调用以及任务依赖。认知保存、导入、纠正、治理、查询与使用在 KSTAR 关闭／缺失时独立完成。KSTAR 自身内部运行不在本轮重构范围，不删除其内部资料，也不为“隔离”清除既有来源出处。

## 8. 不再讨论、不再实施的旧方向

独立待处理页、系统活动全历史管理、默认手动和每日调度、同页侧边详情、纯文本直接编辑主详情、新任务对话页、本体整体暂停、KSTAR 再接入都已经被替换或明确暂不做。

本轮不新引入 Mem0／Semantica／推理引擎／向量数据库，不新增跨设备同步工程，不做永久物理清除，不等待长期效果统计、不改其他应用模块。已存在的同步、隐私和原有资料能力继续兼容。不能借此删掉范围内已确认能力。
