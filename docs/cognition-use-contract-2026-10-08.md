# 认知资产共同使用契约：实施与剩余治理边界

2026-10-08，分支 dev/牛保康-10.1，施工基线8794195c。


## 2026-10-08：共同使用契约收敛（当前实施批次）

本节覆盖 CA-FR-002/004/005/008/009，以及来源撤权与任务使用的共同验收。查阅、明确选用、默认带入使用同一准入服务，但不混用操作许可。

| 操作 | 语义 | 不得推导的结论 |
|---|---|---|
| inspect | 在授权范围内查目录／原文；适用性单独返回 | 已自动带入、已经采用、效果已验证 |
| explicit_use | 本次任务明确选用；未验证内容保留参考身份 | 自动成为长期默认、成熟度升档 |
| default_injection | 无逐次点名的背景带入；需要默认策略和适用性同时通过 | 只要能查阅就可以自动注入 |

共同结果包含 operation、accessAllowed、relevance、defaultUsePolicy、eligible、mode、reasons、usePolicy。状态、来源撤权、项目／工作区权限、禁止条件、Agent限制为共同硬边界；调用方不得删掉阻断理由来放行。`eligible=true` 不得同时返回 `usePolicy=never`。

普通未验证内容不自动带入，但允许经硬边界检查后的查阅和明确选用。个人长期记忆存在明确的用户授权场景：真实的个人内容确认回执（actor=user、accept／modify）可以允许范围内默认使用；必须由主进程核对原始决定，不信任 lifecycle 单值、自述确认或系统决定。此授权不修改 maturity，不证明效果更好。跨场景确认不提升为自动带入。

画像、普通自动投影、KSTAR背景画像共同调用存量资产准入转换服务；目录与正文读取走 inspect；本次点名挂载走 explicit_use。画像排序真实读取 Map 使用统计。经验目录和正文必须带核验状态，inferred不得展示成confirmed。版本、来源和权限继续在读取时重检。

此批实现的是使用契约与确定性错误修复。KSTAR推断经验的发布链、分类建议与明确授权的分离、旧本体消费者的共同解析，以及真实内容归属迁移，仍是后续治理工作；不得以本批测试通过宣称整个认知资产重构完成。

## 生产入口与调用关系

- formal-assets/runtime：共同纯决策，分开硬边界、相关性与操作。
- prompt-injection.evaluateRecallAssetRuntimeEligibility：解析来源与真实个人记忆确认回执，供所有存量资产消费者调用。
- profile-block、context-projection、KSTAR forecast：后台消费使用 default_injection；选定投影使用 explicit_use。
- recall-tools、asset-steward-tools、experience-tools：查阅使用 inspect，不能借目录许可绕过默认使用策略。
- group_chat.bus：派单点名与挂载使用 explicit_use，保留全部阻断理由。
- experience-catalog：目录保留任务相关性过滤与核验状态；正文读取不等于经验发布或效果验证。
- capability继承保留其冻结版本与默认策略限制，不因查阅许可提高继承权限。

## 回归必须覆盖的反例

1. 同一seed可查／可明确选用，但不能默认带入，结果不能never与允许并存。
2. 不适用内容可在授权目录被查询，但不得自动进入画像；暂停／撤权／范围／禁止条件在三种操作均阻断。
3. 用户明确记住个人偏好，下一次任务可使用；伪造lifecycle与系统回执不能取得同样的许可，成熟度仍为bud。
4. 默认画像从真实Map统计排序，不能静默丢弃计数。
5. 显式挂载、冻结版本、来源撤权、历史引用、修正偏好、幂等回流保持原业务约束。
