# CogSeed Semantica 本地判断设计 v3.3

> 状态：当前产品实施基线。v3.1 和 v3.2 中的 Jev 三闸门设计保留为历史实验记录，不再属于产品运行路径。

## 1. 决策

Semantica 改为 CogSeed 完全内置的能力资产增强通道，不再依赖 Jev 或其他外部判断 API。

- 设置页只保留 Semantica 总开关。
- 产品运行时不读取 Jev Endpoint、模型、API Key 或闸门配置。
- 产品运行时不因 `COGSEED_JEV_*` 环境变量发起网络请求。
- 已保存的 Jev 配置和加密密钥不主动删除，但不再读取、展示或发送。
- `src/main/features/jev/` 暂时保留为隔离的历史实验适配器；只有测试或实验调用方显式注入时才可运行。

## 2. 当前主链路

```text
用户自然任务
  -> 本地硬性治理构建当前回合可用资产目录
  -> 语义检索选择一个高相关入口资产
  -> 在已准入资产内做最多两跳的确定性关系扩展
  -> 按语义分数、关系距离、来源和类型多样性确定性合并排序
  -> 读取最终选中资产正文
  -> 生成回答
  -> 本地检查引用集合、关系方向和直接/间接跳数
  -> 输出回答、资产引用和关系证据回执
```

这里的“资产引用”首先表示资产已通过治理并进入本回合模型上下文，不能单独证明最终回答实际采用了该资产。界面和运行回执必须区分“候选命中”“已带入上下文”和“实际采用”；后者只有在任务或产物证据满足采用口径时才成立。

Semantica 关闭时继续走旧能力资产语义检索，不执行自动关系扩展，也不暴露显式 `ontology_query`。

## 3. 三个本地判断点

### 3.1 查询意图

- 由规则、任务契约和用户本体生成有限候选。
- 唯一候选直接采用；同名实体或等价候选返回澄清。
- 自然任务默认使用 `both` 方向、最多两跳和安全关系白名单。
- 不允许判断器创造资产 ID、实体 ID 或关系。

### 3.2 候选适用性

- 只处理已经通过目录和运行时治理的候选。
- 使用语义分数、关系距离、关系来源、成熟度、作用域和类型多样性排序。
- `conflicts_with` 不作为正向经验注入；`replaces` 仅在明确替代意图下使用。
- 空候选保持为空，不为凑数量恢复弱相关或被治理拒绝的资产。

### 3.3 回答验证

- 检查可见资产引用是否属于本回合证据集合。
- 检查方向性关系是否颠倒。
- 检查“直接/间接”表述是否与证据跳数一致。
- 本地硬检查失败时返回保守证据答案；验证器异常不得吞掉已经生成的回答或文件。
- 普通自然任务不要求在正文中打印资产 ID、关系类型或跳数；这些信息保留在引用卡和审计回执中。

## 4. 保留的扩展边界

意图、候选和回答验证模块仍允许调用方显式注入一个“有限候选判断器”。该接口只用于隔离实验，不由设置页、环境变量或生产运行时自动创建。未来接入其他本地模型时，也必须满足：

1. 只能判断 CogSeed 已生成的有限候选。
2. 不能绕过目录、权限、版本、敏感度和生命周期治理。
3. 不能修改本体、关系或正式资产。
4. 失败时保持本地确定性结果。

## 5. 验收方式

产品验收由三组简化为两组：

| 组别 | Semantica | 预期 |
| --- | --- | --- |
| A | 关闭 | 旧语义检索；零自动关系扩展 |
| B | 开启 | 语义入口 + 本地关系扩展 + 本地验证 |

至少准备 30 个真实脱敏自然任务，覆盖直接关系、两跳关系、无关系、歧义、治理拒绝、弱相关和错误方向。B 只有在复用收益、误召回率、治理绕过率、延迟和人工可接受度均达到门槛后才考虑默认开启。

## 6. 下一阶段

完成用户本体实体与能力资产的自动对齐，以及资产关系候选的持续沉淀：资产生成或更新时提取结构化画像，生成有限关系候选，低风险关系经确定性校验后生效，高风险关系进入待确认区，并使用后续任务反馈调整关系可信度。
